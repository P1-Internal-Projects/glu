# Grand Lakes University (GLU)

The P1 demo site for a fictional university: a Next.js site on Pantheon's Content Publisher, edited
in a Puck-based visual page editor with server-side datasource resolution. Live at
https://grand-lakes-university.college (Pantheon site `grand-lakes-university`).

Beyond the starter kit's basic blocks, GLU registers its own component set in `puck.config.tsx`:
Hero, Page Hero, Feature Section, Card Grid, Stats Bar, Fact Grid, Timeline, Accordion, Video,
Slideshow, Testimonial Slider, CTA and Announcement Banners, Article Section, Listing, Program
Cards, Person Profile and Event Header, plus the site nav, footer and locale switcher, which the
Puck root renders once for every page.

Scaffolded with [`@pantheon-systems/create-p1-starter-kit`](https://www.npmjs.com/package/@pantheon-systems/create-p1-starter-kit),
currently at 0.20.0.

## Getting started

1. Copy the environment file and fill in your credentials:

   ```bash
   cp .env.example .env.local
   ```

   Two variables are required:

   | Variable                  | Description                                                          |
   | ------------------------- | -------------------------------------------------------------------- |
   | `NEXT_PUBLIC_CSS_SITE_ID` | The P1 site ID (GLU: `92f403e4-b910-4a1d-bb22-7e2c02edf5c3`)         |
   | `CSS_API_KEY`             | The P1 API Token generated by the P1 platform to access your P1 site |

   GLU also reads these. `.env.example` documents each one inline:

   | Variable                   | Why                                                                     |
   | -------------------------- | ----------------------------------------------------------------------- |
   | `GLU_PROGRAM_API_BASE_URL` | Drupal site serving the academic program catalog (server-side only)     |
   | `NEXT_PUBLIC_AGENT_URL`    | The in-editor AI chatbot's agent backend                                |
   | `PCC_SITE_ID`, `PCC_TOKEN` | Content Publisher articles (`articles/glu-ai-program`, `privacy-policy`) |
   | `NEXT_PUBLIC_SITE_URL`     | `metadataBase`; without it production drops the hreflang alternates     |
   | `P1_SITE_URL`              | Post-login redirect origin; set per Pantheon environment                |

   Do not set `NEXT_PUBLIC_LD_CLIENT_ID`. Every GLU site uses the SDK's default LaunchDarkly
   environment.

2. Install dependencies and start the dev server:

   ```bash
   npm install
   npm run dev
   ```

   This repo uses npm (`package-lock.json`). Don't mix in pnpm or yarn.

3. Open http://localhost:3000 for the site, or http://localhost:3000/p1 for the page dashboard.

   Additional step-by-step details are in the [P1 developer guide](https://live-p1-docs.pantheonsite.io/dev-guide/dev-guide-getting-started).

## Project structure

```
app/
  page.tsx                      # Site root (renders via Puck)
  layout.tsx                    # Root layout
  styles.css                    # Tailwind entry point
  [...puckPath]/                # Catch-all route for published pages
  api/pcc/                      # Content Publisher article endpoints
  p1/
    (editor)/[[...p1]]/         # Dashboard at /p1, editor at /p1/<path>
    api/[...p1]/route.ts        # API handler for page data
    auth/[...action]/route.ts   # Login / logout callbacks
components/puck/                # Block definitions (starter-kit blocks and glu-* components)
components/puck/blocks/         # Blocks installed from the P1 component registry
  index.ts                      #   where you register them (see "P1 blocks" below)
components/pcc/                 # Content Publisher article blocks
design-system/                  # GLU tokens and globals
lib/remote-datasources.ts       # Datasource registry (REMOTE_DATASOURCE_REGISTRY)
lib/remote-datasource-fetchers.ts  # Fetchers backing those datasources
lib/glu-datasources.ts          # GLU events and people datasources
lib/glu-programs.ts             # Academic programs from Drupal
lib/locales.ts                  # The locales the site serves
middleware.ts                   # Locale routing (never touches /p1 or auth)
i18n/                           # Translation glossary, see i18n/README.md
scripts/                        # Admin scripts against the P1 API (see below)
stories/                        # Storybook stories
puck.config.tsx                 # Puck editor configuration — block registry & categories
```

## Customizing

- **Add a block** — install one from the P1 registry (below), or create a component in
  `components/puck/` and register it in `puck.config.tsx`. Then check it in the editor: fields
  named `image`, `imageUrl`, `…ImageUrl` and similar render as media pickers whatever their type.
- **Add a datasource** — add an entry to `REMOTE_DATASOURCE_REGISTRY` in
  `lib/remote-datasources.ts`, with its fetcher in `lib/remote-datasource-fetchers.ts`, to make
  external data available to block fields through `{{ datasource.field }}` expressions.
- **Change styling** — the project uses Tailwind CSS v4; edit `app/styles.css`, the tokens in
  `design-system/`, or the individual block components.

## P1 blocks

P1 ships a library of marketing, editorial and layout blocks as a shadcn code registry rather than
a package, so the code lands in your project and belongs to you — edit it, restyle it, delete what
you do not want.

```bash
npx shadcn@latest add @p1/pricing
```

The files land in `components/puck/blocks/pricing/`. Registering the block takes three lines in
`components/puck/blocks/index.ts`, which `puck.config.tsx` already spreads:

```ts
import { PricingBlock } from "./pricing/pricing.block";

Pricing: PricingBlock,  // add to p1Blocks

// in p1Categories — create the entry if it does not exist yet:
convert: { title: "Convert", components: ["Pricing"] },
// or, if convert already exists, add to its components array (no duplicate key):
// convert: { title: "Convert", components: ["Pricing", "CtaBanner"] },
```

The install prints the `import` and `p1Blocks` lines for you. Add the block to an existing
`p1Categories` entry, or create one — but never create a second key for a category that
already exists. Repeat for each block you want.

Two things worth knowing:

- The category line is what groups a block in the editor drawer. A block registered in `p1Blocks`
  alone still works but is listed under "Other".
- A block's export name is at the top of `components/puck/blocks/<name>/<name>.block.tsx` and does
  not always match the directory — `@p1/logos` exports `LogoCloudBlock`.

Blocks you never register cost nothing. To see what we changed in a block you have already edited,
without overwriting your work:

```bash
npx shadcn@latest add @p1/pricing --diff components/puck/blocks/pricing/pricing.tsx
```

## Localization

The site serves three locales, defined in `lib/locales.ts`: English (`en-US`, no prefix), Spanish
(`es-US`, under `/es`) and Canadian French (`fr-CA`, under `/fr`). Adding a language is a code
change as well as a P1 market setting: the prefix, the switcher and the hreflang alternates all
read that list. `i18n/README.md` covers the translation glossary.

## Storybook

Stories live in `stories/`. The built Storybook is committed under `public/storybook/` and served
by the site at `/storybook`, so run `npm run build-storybook` and commit the output after changing
a component's stories.

## Deploying

The site is hosted on Pantheon (`grand-lakes-university`) and builds from this repo. Merges to
`main` deploy to dev. Test and live deploy from tags:

```bash
git tag pantheon_test_22 && git tag pantheon_live_22
git push origin pantheon_test_22 pantheon_live_22
```

Use the next number after the latest existing tag (`git tag --sort=-creatordate | head`).

## Admin scripts

`scripts/` holds Node scripts that talk to the P1 (CCR) REST API directly. They need an `aak_`
agent key, read from `P1_AGENT_KEY` or `CSS_AGENT_KEY` in `.env.local`; a `sat_` site token
cannot write documents. Each script documents its usage at the top of the file.

**`scripts/p1-admin.mjs` hardcodes GLU's site id (`SITE_ID`).** In a copy of this repo, change it
first, or every script writes to GLU itself.

| Script                                  | What it does                                                    |
| --------------------------------------- | --------------------------------------------------------------- |
| `p1-admin.mjs`                          | Shared API helper (`api()`, `SITE_ID`) the other scripts import |
| `export-p1-site.mjs`                    | Read-only export of a P1 site: every workstream, version and template |
| `import-p1-site.mjs`                    | Writes an export's main workstream into a fresh site, in dependency order |
| `import-p1-workstreams.mjs`             | Recreates the non-main workstreams on a copy                    |
| `verify-p1-copy.mjs`                    | Compares a copied site against its export                       |
| `provision-content-types.mjs`           | Creates the Event and Counselor templates and their pages       |
| `create-program-detail-template.mjs`    | Creates the `/academic-programs/:code` route template           |
| `create-translations.mjs`               | Creates a market version of every translatable page             |
| `i18n-strings.mjs`                      | Extracts and applies a locale variant's translatable strings    |
| `localize-internal-links.mjs`           | Points a translated page's links at the translated pages        |
| `localize-listing-filters.mjs`          | Points each translated page's listing at its own language       |
| `check-locale-paths.mjs`                | Flags translations stored outside the URL convention            |
| `sync-puck-registry.ts`                 | Syncs the component registry without opening the editor         |
| `audit-ai-hints.ts`                     | Reports which components and fields carry AI hints              |

The rest (`es-us-revisions`, `migrate-listing-blocks`, `strip-site-chrome`) are one-off content
migrations kept for reference.

### Copying the site

GLU-2 through GLU-7, GLU-Debug and GLU Demo are copies of this repo and its content. To make
another:

1. Create the P1 site as a signed-in user (agent keys cannot), then grant the agent key admin on
   it.
2. Copy this repo and change `SITE_ID` in `scripts/p1-admin.mjs`.
3. `export-p1-site.mjs` from GLU, `import-p1-site.mjs` into the copy, then
   `verify-p1-copy.mjs`. Check the live copies as well as the published versions afterwards:
   content written through `/versions` alone can be reverted by a later publish.
4. Set the home page's locale to `en-US`; the welcome page a new site starts with has none.
5. Create the Pantheon site against the repo, set the environment secrets listed above, and link
   the P1 site to it.

Images keep pointing at GLU's media library on the public CDN.

## Updating

The scaffolder records the version it generated from under `p1.templateVersion` in
`package.json`. Compare it against the latest published `@pantheon-systems/create-p1-starter-kit`
to see whether newer starter-kit changes are available. Its `template/README.md` changes too, so
fold those into this file when upgrading.
